FreeEDR - PROJECT STRUCTURE AND AGENT ENTRY POINT
==================================================
Every AI agent session starts here. Read this file, then ONLY the docs the routing table (section 4) names for your
task. Do not read every doc: each file under docs\ starts with a "Read for:" line, so you can stop early if it does not
apply.

WHAT FreeEDR IS
  Free single-PC EDR + Wail2Ban for Windows 10/11 x64, built from free tools (Sysmon, YARA, Hayabusa/Sigma,
  OSV-Scanner, Velociraptor, Microsoft Defender). DETECT-ONLY: it detects, explains and logs; it never stops, deletes or
  quarantines anything. The only part that enforces is Wail2Ban (inbound firewall bans of addresses that keep failing to
  sign in; can be switched to report-only). C# 14 / .NET 10, every program NativeAOT (no runtime to install):
    - FreeEDR-Engine.exe     Windows service "FreeEDR" (LocalSystem): detection, Wail2Ban, scans, health
    - FreeEDR-Tray.exe       Avalonia dashboard + tray icon, unelevated, one per signed-in account
    - FreeEDR-Control.exe    elevated helper (UAC): validates one request from the tray, drops it into control\
    - FreeEDR-Installer.exe  install / upgrade / repair / uninstall (run by FreeEDR-Setup.exe and Settings > Apps)
  Installed to C:\Program Files\FreeEDR (admin-only).


1. HARD RULES (every session)
-----------------------------
  - After EVERY code change: dev_build.cmd (through cmd.exe, full path; all gates pass), then UNELEVATED
      powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1
    Read tests\results\last-run.txt, look into EVERY FAIL and WARN, report the TEST RESULT line and every SKIP that
    left your change untested. A FAIL means the change is not done.
  - Never run compiled\FreeEDR-Setup.exe or FreeEDR-Installer.exe (install/uninstall) on the owner's PC without explicit
    approval (they change Defender, firewall, Sysmon, the service, the registry).
  - Edit only in this repository, never in C:\Program Files\FreeEDR.
  - Keep docs true: a change to documented behaviour updates the routed doc in the same change. A new doc gets a
    "Read for:" line and a row in section 4.
  - Known FAILs/WARNs before you start: docs\history\STATUS.md (do not chase those).
  - Every code change adds its entry to docs\CHANGELOG.md under "## Unreleased": a plain-English line under "What's new
    for you" and a line under "Technical" (the build fails without one once a release tag exists). Never edit a released
    section; releases promote Unreleased (docs\agents\AGENT_WORKFLOW.md §3a).
  Full loop, build gates, test suites and design rules: docs\agents\AGENT_WORKFLOW.md (ALWAYS read it when you edit files).


2. CI/CD FLOW FOR AGENTS
------------------------
  project_structure.txt (this file)
     -> routed docs for the task (section 4)
     -> edit in the repo
     -> dev_build.cmd                                   gates: data files/encodings -> C# tests -> NativeAOT publish of
                                                        4 programs -> live tray self-test -> staging (+signing) -> Inno Setup
     -> tests\Run-Tests.ps1 (unelevated)                01-Sanity 02-Unit 03-FalsePositive 04-PenTest 05-Live
     -> review last-run.txt, fix or justify every FAIL/WARN
     -> update routed docs + docs\history\STATUS.md + docs\CHANGELOG.md (Unreleased)
     -> report (TEST RESULT line, SKIPs)
     -> install only with the owner's approval, then re-run the tests (05-Live checks the installed copy)
  Commits / pushes only when the owner asks. Releases: only the owner, with .github\workflows\release.yml
  (Actions > Release: changelog promotion, build, tests, verified draft, publish, five newest installers kept; tick
  "Dry run" to prove the whole path without publishing).

5. KEY INVARIANTS (short form; details in the routed docs)
----------------------------------------------------------
  - Detect-only: no FreeEDR code stops a process, deletes or quarantines a file. Wail2Ban bans are the one enforcement.
  - The engine (SYSTEM) must never stop: every step inside Engine.Safely; the service restarts itself on failure.
  - The tray is unelevated: reads the install folder, writes only user\<SID>\ and inbox\ (and its own notification
    registration under HKCU). Every weakening change goes UAC -> FreeEDR-Control.exe -> control\ -> PatternRules
    validation again in the engine. inbox\ accepts only resume / scan-now. The confirmation shows the whole request
    or the helper refuses it. Files in user-writable folders: Native\DropFile, never on the engine's main loop.
  - Only the engine writes data\events.jsonl (other FreeEDR programs: EngineNote.Send).
  - Paths only from EdrPaths; everything FreeEDR keeps lives under the install folder.
  - Installer changes outside the folder are recorded (preinstall.json / managed.json) and undone by the uninstaller;
    never lower a Windows protection setting that was stronger before FreeEDR.
  - NativeAOT everywhere: no reflection-based JSON or bindings (JsonNode, code-built views); trim/AOT warnings are errors.
  - .yar = ASCII without BOM; .ps1 (tests) = UTF-8 with BOM, Windows PowerShell 5.1.
